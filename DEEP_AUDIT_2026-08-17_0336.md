| §9 mechanism | Status |
|---|---|

## 6. What is left — consolidated

### From the Desktop Environment Master Prompt (the active roadmap)
1. **Phase S — App launcher / taskbar** (the only unimplemented phase):
   taskbar region listing open windows + launch icons; click-to-launch a
   new editor/browser instance; click a taskbar entry to bring a window to
   front. DoD: cold boot → mouse-only launch of both apps → click between
   them → edit + save a file found via the browser. None of this exists.
   Reusable primitives already present: click-to-focus-content
   (`focus_content_press`), Tab-raise z-order (`cycle_focus`), and the
   existing status-bar concept to extend.

### From `os-from-first-principles.md` (the design doc)
Ordered by this audit's phase scores (lowest first):

1. **§7 Phase 12 tail: real-hardware certification** — nothing has run on
   physical hardware. QEMU/TCG and VMware are the only execution
   environments. No secure boot/attestation, no coverage-guided fuzzing.
2. **§7 Phase 9 tail: Windows VM fidelity** — the VT-x primitive has never
   executed on a VMX-capable CPU; no EPT/vmresume/NT guest image.
3. **§7 Phase 8 tail: Linux lightweight-VM vehicle** — not built; only the
   narrow `int 0x80` ring-3 trap variant.
4. **§7 Phase 7 tail: object/relationship-based shell** — `object_graph.rs`
   is not wired into the live desktop; the desktop is window-based; no
   app-manifest launch model; **no launcher/taskbar** (Phase S above).
5. **§8 Graphics: GPU command engine** — capability-scoped GPU command-queue
   submission not built (framebuffer only).
6. **§8 Device model: userspace drivers** — all drivers kernel-resident;
   the design's IOMMU-backed userspace-driver model is not implemented.
7. **§9 (the doc's self-named hardest problem): delegation UX** —
   ephemeral/time-boxed grants, persistent-grant confirmation, diff-based
   confirmation, and kernel-side two-party confirmation are all unbuilt.
8. **§8 Developer experience: capability-typed language bindings, static
   flagging, capability-graph tooling** — not started.
9. **§8 Application model: kernel app-manifest system** — not started.
10. **§10 IPC fast-path class** (trusted read-only map into a caller's
    address space) — not built (batched submission and shared-memory grants
    are).
11. **seL4-class kernel proof** — explicitly declined by this project's own
    roadmap (keep the from-scratch kernel, grow its capability model). This
    is a documented decision, not an oversight, but it remains true that
    the kernel is not formally verified.

### Things that are *inherent* per the design doc and will not close (do not chase)
- Distributed transparency under partition (CAP) — handled via fail-closed
  visibility, as designed.
- Proving AI agent behavior vs its ceiling — ceiling verified, behavior
  bounded by monitoring, as designed.
- The compatibility moat — handled via translation + (reduced) VMX, as
  designed.
- A human being socially engineered into granting too much — reduced by
  roles + audit + anomaly monitoring, not eliminated (doc says so plainly).
